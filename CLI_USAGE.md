## Creating a project

### `loom init` / `loom new`

```bash
loom init my-app                              # interactive (6 prompts)
loom init my-app --preset saas --no-install   # non-interactive
loom new my-app                               # alias for loom init
cd my-app && pnpm dev                         # uses your chosen PM
```

Interactive prompts (6):
1. **Project name** — defaults to the argument
2. **Package manager** — pnpm, npm, yarn, or bun (persisted in `.loom/metadata.json`)
3. **UI preset** — saas, clinic, studio, operations, commerce, or custom
4. **Design theme** — 8 color themes with descriptions
5. **Layout shell** — 4 layout options
6. **Install dependencies?** — run the selected PM's install or skip

#### Options

| Flag                      | Values                                                                                                                | What it does                                                              |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `--preset <variant>`      | `saas`, `clinic`, `studio`, `operations`, `commerce`, `custom`                                                       | Select a starter preset shape                                             |
| `--theme <theme>`         | `executiveBlue`, `clinicSoft`, `studioElevated`, `operationsDense`, `commerceWarm`, `violetSanctum`, `tealFlow`, `warmNeutral` | Choose the UI theme palette (8 built-in)                       |
| `--layout <layout>`       | `hybridSaas`, `sidebarWorkspace`, `topbarPortal`, `rightRailStudio`                                                   | Choose the app shell layout                                               |
| `--brand-name <name>`     | any text                                                                               | Set the brand name used in README/brand files                             |
| `--tagline <text>`        | any text                                                                               | Set the slogan/tagline used in the project                                |
| `--extra-modules <list>`  | `users,products,...`                                                                   | Include additional backend modules in the starter app                     |
| `--deploy-targets <list>` | `docker,vercel,railway`                                                                | Generate deployment config for the selected targets                       |
| `--architecture <level>`  | `lightweight`, `moderate`, `advanced`                                                  | Choose the default generated architecture complexity                      |
| `--scenario <name>`       | `parking`, `payroll`, `inventory`, `booking`, `delivery`                               | Auto-scaffold a scenario preset after init                                |
| `--no-install`            | —                                                                                      | Skip dependency install after scaffold creation                           |
| `--target <dir>`          | any path                                                                               | Write the new project into a custom directory                             |
| `--force`                 | —                                                                                      | Overwrite an existing target directory or continue past validation issues |
| `--local-template <path>` | path                                                                                   | Use a local template tree instead of downloading                          |
| `--template <name>`       | template key from `config/templates.json` (default: `mern`)                            | Select a template source by name                                          |

#### Common errors

| Error | Cause | Fix |
| ----- | ----- | --- |
| `local template path does not exist` | Typo in `--local-template` | Use the absolute path shown in the error |
| `Template validation failed` | Template missing required files | Check the printed path with `ls -R` |
| `HTTP 404 from github.com` | Wrong repo/branch in config | Pass `--local-template` or fix `config/templates.json` |

## Generating code

### `loom generate resource`

The flagship command — creates a full-stack CRUD resource in one shot.

```bash
# Auto-interactive (no flags needed)
loom generate resource Product

# Quick mode
loom generate resource Product \
  --fields "name:string:required;price:number;category:string" \
  --crud full --arch moderate

# Backend-only
loom generate resource Product --fields "name:string" --no-frontend

# Preview without writing
loom generate resource Product --fields "name:string" --dry-run
```

What it generates (for a Product with full CRUD, moderate arch):

```
backend/src/modules/product/
  models/Product.js              # Mongoose schema
  services/product.service.js    # Business logic
  controllers/product.controller.js
  routes/product.routes.js
  validators/product.validator.js

frontend/src/
  pages/admin/products/
    ProductListPage.jsx
    ProductDetailPage.jsx
  components/tables/ProductTable.jsx
  components/forms/ProductForm.jsx
  hooks/useProduct.js
  api/product.api.js

Injections:
  backend/src/routes/index.js        # Route mounted at /api/products
  frontend/src/routes/AppRouter.jsx   # Lazy import + route
  frontend/src/config/app-preset.js   # Nav entry
```

#### Options

| Flag                 | Values                                 | What it does                                                          |
| -------------------- | -------------------------------------- | --------------------------------------------------------------------- |
| `--fields <spec>`    | `name:type:rules;...`                  | Define the resource schema inline                                     |
| `--file <path>`      | file path                              | Load schema from a resource definition file                           |
| `--recipe <name>`    | `resource`, `module`, `page`           | Choose the kind of generation                                         |
| `--arch <level>`     | `lightweight`, `moderate`, `advanced`  | Choose how much backend structure is generated                        |
| `--form-mode <mode>` | `page`, `modal`, `sidepanel`, `inline` | Choose how the form is mounted in the UI                              |
| `--crud <mode>`      | `full`, `insert-only`                  | CRUD scope — insert-only skips list/detail/update/delete              |
| `--with-tests`       | —                                      | Generate test files for the resource                                  |
| `--no-frontend`      | —                                      | Skip frontend generation, backend-only output                         |
| `--interactive`      | —                                      | Prompt for missing resource details interactively                     |
| `--dry-run`          | —                                      | Preview the file plan without writing any changes                     |
| `--preview`          | —                                      | Show estimated file count, time, and planned files before generating  |
| `--relations <spec>` | `virtual:hasMany:Model:foreignKey;…`   | Mongoose virtual `hasMany` populate (see below)                       |
| `--amend`            | —                                      | Update an existing resource; merge --fields, preserve custom zones    |
| `--remove-fields`    | comma-separated                        | Remove fields by name on amend                                        |
| `--force`            | —                                      | On amend, overwrite unmarked files                                    |

### `loom resource sync` (amend)

Update an existing resource without losing custom code.

```bash
loom resource sync Product --fields "sku:string:required"
loom resource sync Product --remove-fields "oldField"
loom resource sync Product --interactive    # menu-driven
```

| Flag              | What it does                                    |
| ----------------- | ----------------------------------------------- |
| `--remove-fields` | Comma-separated field names to drop              |
| `--force`         | Overwrite files without markers / custom zone   |
| `--interactive`   | Walk through add/remove fields and relations    |

> Requires a prior `generate resource` for that name. Schema saved in `.loom/resources/<kebab>.json`.

#### Common errors

| Error | Cause | Fix |
| ----- | ----- | --- |
| `Amend refused: manual edits detected` | Code outside safe zones | Move custom code below `CUSTOM CODE ZONE` marker, or use `--force` |
| `No stored definition for Product` | No prior `generate resource` | Generate the resource first |

### `loom add-report`

Generate an aggregation pipeline report.

```bash
# Interactive
loom add-report sales-summary

# Quick mode
loom add-report top-products \
  --model Product \
  --group-by category \
  --agg-fn sum \
  --agg-target price
```

#### Options

| Flag               | Type                           | What it does                          |
| ------------------ | ------------------------------ | ------------------------------------- |
| `--model <name>`   | string (PascalCase)            | Mongoose model name                   |
| `--title <text>`   | string                         | Report title                          |
| `--description`    | string                         | Report description                    |
| `--group-by`       | field name                     | Group by field                        |
| `--agg-fn`         | `sum|count|avg|min|max`        | Aggregation function                  |
| `--agg-field`      | string                         | Result field name                     |
| `--agg-target`     | field name                     | Field to aggregate on                 |
| `--sort-by`        | field name                     | Sort by field                         |
| `--sort-order`     | `asc|desc` (default: desc)     | Sort direction                        |
| `--interactive`    | —                              | Prompt for all details                |
| `--no-frontend`    | —                              | Skip frontend generation              |

#### Aggregation functions

| Function | Description         | Example                          |
| -------- | ------------------- | -------------------------------- |
| `sum`    | Sum of values       | Total revenue per category       |
| `count`  | Number of documents | Orders per customer              |
| `avg`    | Average value       | Average rating per product       |
| `min`    | Minimum value       | Lowest price per category        |
| `max`    | Maximum value       | Highest salary per department    |

### `loom doctor` / `loom check` / `loom env`


### `loom finalize` / `loom cleanup`

```bash
# Production readiness
loom finalize          # Lint → test → build → audit (uses your PM)

# De-branding
loom cleanup minimal       # Remove demo content, reset package identity
loom cleanup production    # Full de-brand (removes .loom/, docs, branding)
loom cleanup template      # Extract reusable components into .template/
```

**`loom finalize`** runs: lint, TypeScript check, tests, build, and security audit.

**`loom cleanup production`** removes `.loom/`, bundled CLI, starter docs, demo content;
strips `STARTER-KIT:` / `TODO: Customize` comments and AUTO-GENERATED markers;
resets package names; rewrites README — leaving zero trace of the starter kit.

> `cleanup` refuses to run unless the working directory is a real project root
> (has both `backend/` and `frontend/`).

### `loom upgrade` / `loom backup`

```bash
# Compatibility check
loom upgrade

# Apply safe migrations
loom upgrade --write

# Preview changes
loom upgrade --dry-run

# Force overwrite unmarked files
loom upgrade --write --force

# Manage backups
loom backup list
loom backup restore <id>
```

The upgrade engine preserves user code:
- Files with `AUTO-GENERATED` markers: only the marked block is replaced.
- Files without markers: backed up as `.upgrade-new` sidecars.
- `--force`: overwrite everything.

> Always commit your project to git before running `loom upgrade --write`.

## Field spec format

Each field follows `fieldName:type:rule1|rule2`:

```bash
--fields "name:string:required;price:number:required|min=0;category:ref[Category]"
```

### Type aliases

| Alias | Resolves to |
| ----- | ----------- |
| `str` | `string` |
| `num` | `number` |
| `bool` | `boolean` |

### Supported types (22 total)

| Type | Form input | Mongoose | Notes |
| ---- | ---------- | -------- | ----- |
| `string` | Text | String | Default type |
| `text` | Textarea | String | Long text |
| `richtext` | Textarea | String | Full-text indexed |
| `number` | Number | Number | — |
| `range` | Range slider | Number | — |
| `boolean` | Checkbox | Boolean | — |
| `date` | Date picker | Date | Installs date-fns + react-day-picker |
| `datetime` | Date + time picker | Date | Installs date-fns + react-day-picker |
| `time` | Time input | String | — |
| `email` | Email | String | Built-in email validation |
| `password` | Password | String | Min 8 chars validation |
| `phone` | Tel | String | E.164 format validation |
| `url` | URL | String | URL validation |
| `color` | Color picker | String | Hex color |
| `file` | File upload | String | Configurable upload dir + size limit |
| `image` | Image upload + preview | String | Configurable upload dir + size limit |
| `select[opt1,opt2]` | Dropdown | String | Enum options in brackets |
| `multiselect[opt1,opt2]` | Multi-select | Array | Multiple enum values |
| `ref[Model]` | Searchable combobox | ObjectId | MongoDB reference, fetches from API |
| `reference[Model]` | Searchable combobox | ObjectId | Alias for ref |
| `array` | Text | Array | Mongoose array |
| `object` | Text | Object | Mongoose nested object |

### Bracket syntax for special types

Some types accept bracket `[…]` content after the type name:

| Syntax | Example | Effect |
| ------ | ------- | ------ |
| `select[opt1,opt2]` | `status:select[pending,active,archived]` | Dropdown with predefined choices |
| `multiselect[opt1,opt2]` | `tags:multiselect[node,vue,react]` | Multi-select with predefined choices |
| `ref[Model]` | `category:ref[Category]` | MongoDB ObjectId referencing another model |
| `image[dir;max=N]` | `avatar:image[avatars;max=2mb]` | Upload directory + max file size |
| `file[dir;max=N]` | `resume:file[docs;max=10mb]` | Upload directory + max file size |

### Inline bracket rules (alternative to pipe syntax)

Instead of `|`-separated rules, use `[key=value,flag]` after the type:

```bash
# Inline bracket: min, max, pattern, default, required, unique
price:number[min=0,max=9999]
code:string[pattern=/^[A-Z]+$/,required]
quantity:number[min=1,default=0]
startDate:date[min=2024-01-01]
```

Works for all types **except** `ref[Model]`, `select`, `multiselect`, `image`, `file`.

### Validation rules

| Rule | Example | Effect |
| ---- | ------- | ------ |
| `required` | `name:string:required` | Field is mandatory |
| `unique` | `email:email:unique` | Mongoose unique index, duplicate check on save |
| `minLength=N` | `name:string:minLength=2` | Minimum string length |
| `maxLength=N` | `bio:text:maxLength=500` | Maximum string length |
| `min=N` | `age:number:min=0` | Minimum numeric or date value |
| `max=N` | `price:number:max=9999` | Maximum numeric or date value |
| `pattern=REGEX` | `code:string:pattern=/^[A-Z]+$/` | Regex validation (Mongoose match + Joi pattern + Zod regex) |
| `default=X` | `status:string:default=active` | Default value for the field |

### Full examples

```bash
# Simple
--fields "name:string;age:number;active:boolean"

# With validation
--fields "email:email:required|unique;age:number:required|min=18|max=120"
--fields "code:string:required|minLength=2|maxLength=50|pattern=/^[A-Z]+$/"

# Type aliases
--fields "name:str;count:num;active:bool"

# Reference fields
--fields "category:ref[Category]:required;department:reference[Department]"

# Select/Multiselect with options
--fields "status:select[pending,active,archived]:required|default=active"
--fields "tags:multiselect[node,vue,react]"

# Upload types with directory and size limit
--fields "avatar:image[avatars;max=2mb];resume:file[docs;max=10mb]"

# Inline bracket rules (alternative to pipe syntax)
--fields "price:number[min=0,max=9999,required]"
--fields "code:string[pattern=/^[A-Z]+$/,required]"
```

### Auto field type inference

Interactive mode suggests the field type based on name:

| Name pattern | Suggested type |
| ------------ | -------------- |
| `email`, `mail` | email |

## Relations spec

Two kinds of relations:

### belongsTo (3 parts)

```bash
--relations "employee:belongsTo:Employee"
```

Creates a `ref[Employee]` field named `employee` on the current model, wires up the combobox form input that fetches options from the referenced model's API. The `belongsTo` relation is the recommended way to create ref fields.

### hasMany / virtual populate (4 parts)

```bash
--relations "orders:hasMany:Order:customerId"
```

Format: `virtualFieldName:hasMany:ChildPascalModel:foreignKeyOnChild`

Adds a Mongoose virtual populate to the parent model so `parent.orders`
resolves to all `Order` docs where `order.customerId === parent._id`.
The detail page shows linked records in a related card.

### Multiple relations

Separated with `;`:

```bash
--relations "employee:belongsTo:Employee;orders:hasMany:Order:customerId"
```
